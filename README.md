# wakariyasu

[English](README.en.md)

wakariyasu は、AI エージェントが書く日本語を、作業の経緯を知らない人が読んでも分かるようにする、Claude Code のプラグインです。エージェントがユーザーに返す報告や質問と、エージェントが書く文書（README・仕様書・コミットメッセージなど）の両方に効きます。

エージェントに長い作業を任せると、報告や質問が、作業の途中でエージェントが付けた呼び名や、途中で決めた前提のまま書かれがちです。報告を読む人は「結局どういうこと？」と聞き返すことになります。wakariyasu はエージェントへの指示文を足して、経緯を知らない読み手に通じる形で書かせます。

## 入れる前と後

ウェブアプリの修正を頼み、作業が終わったときの報告です。

入れる前:

> 案Aで進め、キャッシュは v2 に寄せました。残りは例のエラーだけです。

入れた後:

> 商品一覧の画面が遅い件は、表示のたびにデータベースから読んでいた商品の情報を、5分間手元に残す形にしました。表示にかかる時間は 2.1 秒から 0.4 秒になりました。残っているのは、在庫が0の商品で画面の表示が崩れる不具合の1件です。

入れる前の報告は作業中にだけ通じる「案A」「v2」「例のエラー」で書かれていて、読む人は作業の経緯を追わないと意味が分かりません。入れた後は何をして、何が変わり、何が残っているかが、報告だけで分かります。

## 規則とスキル

wakariyasu はエージェントへの指示文でできていて、指示文には2種類あります。

- **規則**は書き方の方針を書いた指示文です。Claude Code では、セッションが始まるたびに読み込まれ、毎回の返答と文書に当てはめられます。頼む必要はありません。
- **スキル**は決まった場面での手順を書いた指示文です。ユーザーが下の表の言葉で頼んだとき、またはエージェントが報告を書くときや文書を書き上げて渡すときに、エージェントが自分で選んで使います。

## 使う場面

| 場面 | 言葉の例 | 使われる指示文 | すること |
|---|---|---|---|
| いつもの返答 | （頼まなくても当てはまります） | 規則 `writing-to-user` | 返答を、経緯を知らない人に通じる語と形で書かせます |
| 状況を知りたい | 「現状は？」「残タスクは？」 | スキル `session-status` | 目指していること・タスクと状態・判断を求めることを、決まった形で報告させます |
| 返答が分からない | 「分かりやすく」「つまり？」「〜とは？」「〜の違いは？」 | スキル `explain-clearly` | 直前の返答や、その中の分からなかった語を言い直させます。「簡潔に」なら短く、「小学生でも分かるように」なら前提を足して説明させます |
| 文書を書かせる | （頼まなくても当てはまります） | 規則 `writing-documents` | README・仕様書・SKILL.md・コミットメッセージなどを、その文書だけで通じるように書かせます |
| 文書からメタ記述を除く | 「メタ記述を除いて」 | スキル `remove-meta-narrative` | メタ記述（「本章では〜」「ご指摘を受けて〜」のように、文書が自分自身や作った経緯を語る文）を見つけて直させます |
| 文書を人に渡す前 | 「公開前に見て」「読み手の目でレビューして」 | スキル `review-for-readers` | 作業の経緯を知らない別のエージェント（サブエージェント）に文書だけを読ませ、その読み手が引っかかった箇所を直させます。サブエージェントを起こせないエージェントでは、自分で読み直したことを添えて報告させます |

規則はもう1本、`polishing` があります。書いた日本語を渡す前に整える方法と、下の「表記の選び方」を決めた規則です。

規則は3本合わせて約4,000字で、セッションごとに一度読み込まれます。`review-for-readers` はサブエージェントを起こすので、そのぶん時間とトークンを使います。

## 表記の選び方

かなと漢字の使い分け・数字の書き方・体言止め・常体と敬体は、文章の種類によって変わります。wakariyasu はこれらを一律には決めず、エージェントに次の順で選ばせます。

1. ユーザーの指示（CLAUDE.md や AGENTS.md に書いた指示を含みます）
2. 同じ文書や同じリポジトリで、すでに使われている書き方
3. wakariyasu が文章の種類ごとに決めた既定。たとえば、ユーザーへの返答は敬体の文で書き、コミットや PR の変更点の行は体言止めでもよい、とします。種類ごとの表は [`references/styles.md`](references/styles.md) にあります

決まった書き方にしたいときは、CLAUDE.md に1行で書いてください。たとえば「数字は算用数字で書く」「README は敬体で書く」と書けば、既定よりそちらが優先されます。

## yomiyasu との組み合わせ

[yomiyasu](https://github.com/nanaism/yomiyasu)（nanaism/yomiyasu）は、AI が書いた日本語の、不自然な比喩・主語と述語のずれ・宣伝のような言い回しを整えるスキルです。wakariyasu とは別の作者のものです。wakariyasu が語と構成を読み手に合わせ、yomiyasu が文そのものを整える、という分担になります。

エージェントはどの文章もまず wakariyasu の規則で自分で整えます。長すぎる文、離れすぎた主語と述語、「画期的な」のような中身の無い飾りの語、予告だけの文、前置きの句、間を取るだけの読点などを確かめて直します。この確かめる項目の一部は、yomiyasu の検査項目を参考にしています。yomiyasu を入れていなくても、wakariyasu はこれだけで動きます。

yomiyasu が入っていれば、README や手順書のように人に渡す文書を書き上げたときに、自分で整えたあとで yomiyasu にも通します。そのとき、文章の種類（README・手順書など）も渡します。ユーザーへの返答では yomiyasu を呼びません。Sonnet と Opus で約30回試したところ、返答で yomiyasu を呼ぶと1回あたりの費用が約3倍、時間が約2倍になり、直った箇所は読点などの数か所にとどまりました。

yomiyasu は名前を出して頼まれたときか、CLAUDE.md などの指示で求められたときにだけ動きます。そのため、wakariyasu の規則だけでは呼ばれないことがあります。文書のたびに確実に通したいときは、CLAUDE.md（Claude Code が読む指示のファイル。ほかのエージェントでは AGENTS.md など）に次の1行を書いてください。

```text
人に渡す文書は、仕上げる前に yomiyasu で整える。
```

## 入れ方

### Claude Code に、プラグインとして入れる（勧め）

Claude Code の中で、次の2つを打ちます。1つ目はこのリポジトリをプラグインの入手先（マーケットプレイス）として登録します。2つ目はそこから wakariyasu を入れます（`wakariyasu@wakariyasu` は「プラグイン名@入手先の名前」です）。

```text
/plugin marketplace add kulikala/wakariyasu
/plugin install wakariyasu@wakariyasu
```

規則とスキルの両方が入ります。この入手先には yomiyasu も載せてあり、中身は yomiyasu のリポジトリから入ります。

```text
/plugin install yomiyasu@wakariyasu
```

入ったかどうかは新しいセッションで「現状は？」と聞いて確かめられます。「現在のゴール」「タスク」などの見出しのついた報告が返ってくれば、入っています。

### ほかのエージェントで使う

Codex・Cursor・GitHub Copilot などで使うときは、スキルと規則を別々に入れます。

スキルは GitHub CLI の `gh skill` コマンド（プレビュー版の機能）で入れます。

```sh
gh skill install kulikala/wakariyasu --all --scope user --agent codex
```

`--all` は4本のスキル（session-status・explain-clearly・remove-meta-narrative・review-for-readers）をすべて入れる指定、`--scope user` はホームディレクトリに入れてすべてのフォルダで使えるようにする指定です。`--agent` には、使うエージェントの名前（`codex`・`cursor`・`github-copilot` など）を渡します。

規則は、3本の規則をつなげた [`AGENTS.snippet.md`](AGENTS.snippet.md) の本文を、エージェントが毎回読む指示のファイル（Codex なら AGENTS.md、ほかのエージェントならそのエージェントのカスタム指示）に貼ります。

スキルだけを入れて規則を貼らないと、「いつもの返答」と「文書を書かせる」の場面には何も効きません。スキルは頼んだときと、エージェントが自分で選んだときにだけ動きます。そのときは、各スキルが自分のフォルダに持っている規則の写しを読みます。

## このリポジトリを直す人へ

```text
rules/                  規則（writing-to-user・writing-documents・polishing）
references/styles.md    文章の種類ごとの表記の既定
skills/                 スキル（session-status・explain-clearly・remove-meta-narrative・review-for-readers）
hooks/                  プラグインとして入れたときに、セッションの始めに規則を読み込ませるフック
AGENTS.snippet.md       Claude Code 以外のエージェントに貼る、規則の本文
bin/build               rules/ と references/ の内容を、スキルの中と AGENTS.snippet.md に写す
```

規則と表記の既定は、`rules/` と `references/` だけで直します。直したら `bin/build` を実行し、スキルの中の写しと `AGENTS.snippet.md` を作り直してください。`bin/build --check` は、写しが `rules/` と `references/` の内容と食い違っていれば失敗します。
