# 変更履歴の書き方

公開するツールの変更履歴（CHANGELOG・リリースノート）は、ツールを使っている人と、入れるかを考えている人に向けた、新しいバージョンの案内だ。読み手は変更履歴だけを読んで、ツールを新しいバージョンに更新するか、使い方を変える必要があるかを判断する。

- 読み手がツールを使うときに気づく変化を記載する。できるようになったことと、振る舞いが変わったこと。
- 作り方・内部の手順・細かい仕様は記載しない。変化の詳しい使い方は、ツールの README や手引きの該当する節へのリンクで示す。
- 1つのバージョンの項目は、追加・変更のような変更の種類の小見出しに分けず、1つの並びにする。読み手は変更の種類ではなく、自分に関わる変化を探して読む。読み手がすることのある変化を先に、次に、できるようになったことと振る舞いが変わったことを並べる。
- 1つの項目には、1つの変化を、読み手の側から見た言葉で記述する。ツールの中の名前（関数・ファイル・内部の呼び名）は、読み手が使う名前（コマンド・スキル・設定の名前）のときだけ記載する。
- 読み手が何かをしないと使い続けられない変化（設定の書き換え、入れ直し、使えなくなる機能）は、その項目の中に、読み手がすることまで記載する。
- バージョンの見出しと番号の付け方は、変更履歴の冒頭や開発の手引きに決まりがあれば従い、無ければ変更履歴にある前のバージョンの書き方にそろえる。
