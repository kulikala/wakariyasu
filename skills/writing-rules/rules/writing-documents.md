# エージェントが記述する文書は、文書だけで通じるように記述する

README・仕様書・設計書・手順書・規則・SKILL.md・プロンプトのような文書は、作成したときの
やり取りを知らない人が読む。読み手が文書だけを読んで分かるように記述する。

## 文章の種類で経緯の扱いが変わる

| 文章の種類 | 載せる内容 | 作業の経緯 |
|---|---|---|
| ユーザーへの返答 | 状況と、ユーザーに判断してもらうことがあれば、判断してもらう内容 | 状況の理解に必要な分だけ、何をしたか・何のためかを記述する（規則「ユーザーへの返答は、経緯を追っていない人が読んで分かるように記述する」（`writing-to-user.md`）） |
| 文書の本文 | 対象自体 | 記述しない。文書だけを読む人に向けて記述する |
| コミットメッセージ・PR の本文 | 何を変えたか、なぜ変えたか | 変えた理由は記述する。試した順番や苦労は記述しない |
| 公開する変更履歴 | 新しいバージョンで、使う人に届く変化 | 記述しない。作り方や内部の手順も記述しない |
| コードのコメント | コードが今の形になっている理由 | 記述しない。経緯はバージョン管理の履歴に任せる |
| 作業記録・進行記録 | 何をして、何が分かり、何が残っているか | 記述する。作業自体を記録する文書なので、作業の途中の出力（「〜は未達」「〜は不明だった」）も残す |

どれに当たるか迷ったら、やり取りを知らない人が、渡した文章だけを読むことがあるかで判断する。
読むなら文書として記述する。返答の中に文書の全文を載せるときは、全文の部分を文書として記述する。

## 文書の本文の書き方

- 対象自体を語る。文書自身の構成（「本章では」）、作った経緯（「ご指摘を受けて」）、
  指示への応答（「ご依頼の一覧です」）は記述しない。
- 文書の外にあるものを前提にしない。会話の中で決定した事項・別の文書・会話の場での合意が要るなら、
  必要な分を本文に記載する。
- 語が示す対象を、語と一緒に読まれる範囲（節・表の1行・スライドの1枚など）の中に置く。
  読み手は範囲の中だけを拾って読むことがある。指示語（「これ」「その」「こう」のようなこそあど言葉）は
  使わず、示す対象の名前を記載する。前の状態を示す語（「もう」「すでに」）は、状態自体を記述する。
  「何の」「誰の」が無い一般語と、何と比べたかの無い「だけ」も、何の・誰の・何と比べてかを記載する。
- 書き手が作った呼び名を説明なしに続けて使わない。「戦略的」「最適化」のように中身が
  決まらない語で済ませず、何をどうするかを記述する。
- 動く人を文に残す。誰が何をするかを受け身や名詞の並びで消さない。
- 数には確かさを添える。測った値か見積もりか、何を含まないかを記載する。
- スキル・規則・プロンプトのように、エージェントが読んで動く文書は、
  「エージェント向けの指示文の書き方」（`writing-instructions.md`）を読んで、沿う。
- リポジトリの最上位に置き、ツールを外部に公開する README（ツールが何であり、どうセットアップすれば使えるかを
  伝える文書）を記述・修正するときは、「README の書き方」（`readme.md`）を読んで、沿う。
- 公開するツールの変更履歴（CHANGELOG・リリースノート）を記述・修正するときは、「変更履歴の書き方」（`changelog.md`）を読んで、沿う。

## 書き終えたら

仕上げの手順は次の4つ。

1. `remove-meta-narrative` スキルで、作業の経緯や文書自身を語る文と、作業の途中の出力（「〜は未達」「〜は不明だった」）を探して修正する。
2. 人に渡す・公開する文書は、`review-for-readers` スキルで、経緯を知らない読み手の視点で読み直す。
3. 規則「記述した文章は、渡す前に整える」（`polishing.md`）に沿って自分で整える。読み込まれていなければ `polishing.md` を読む。
4. 人に渡す日本語の文書は、使えるスキルの中に yomiyasu があれば、yomiyasu スキルを呼び出し、
   文書と文章の種類を渡す。

手順 2 の `review-for-readers` スキルは、手順 3 と 4 もスキルの中で行う。

文書の種類に応じて、手順の前にすることと、行う手順を選ぶ。

| 文書の種類 | 仕上げ方 |
|---|---|
| スキル（SKILL.md と、スキルが読むリファレンス） | `clarify-skill` スキルで、スキルを読んだエージェントがスキルの目的から判断できる指示文かを点検して修正してから、手順 1〜4 |
| 公開する README | 「README の書き方」（`readme.md`）に沿っているかを確かめてから、手順 1〜4 |
| 公開する変更履歴 | 「変更履歴の書き方」（`changelog.md`）に沿っているかを確かめてから、手順 3・4。変更履歴は前のバージョンとの差を伝える文書で、手順 1 は前のバージョンとの差を記述した文を修正してしまうので、行わない |
| コミットメッセージ・PR の本文 | 手順 3 |
| そのほかの文書 | 手順 1〜4 |
