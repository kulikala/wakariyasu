# 文書からメタ記述を除く

文書は対象（仕組み・仕様・提案の中身）自体を語る。文書自身・作った経緯・書く行為・
指示への応答は語らない。読み手は、渡された時点の文書だけを読む。

適用するのは文書の本文。ユーザーへの返答や作業の報告は、何をしたかを書くのが役目なので適用しない。
コミットメッセージと PR の本文は、何をどう変えたかを書くのが役目なので、群3のうち前のバージョンとの差は
適用しない。試した順番や苦労（群3）と、群4・群5だけを適用する。
作業記録・進行記録・検証の記録・議事録・変更履歴のように、作業自体を記録するための文書には、群4と群5を適用しない。

## 5つの群と、見分けるための質問

| 群 | よく出る形 | 見分けるための質問 |
|---|---|---|
| 1. 文書が自分を語る | 「本章では〜を説明する」「（本書の中核）」「本書は〜を前提とする」「本資料は後続の設計の入力とする」「この文書は〜の基準で書く」 | 消したとき、対象についての情報が減るか |
| 2. 文書が外を参照する | 「詳細は後述」「前述のとおり」「上記のとおり」「別紙を参照」 | 文書だけを読んで、参照先が分かるか |
| 3. 作った経緯が残る | 「まず次の原則を固定する」「レビューの指摘を受けて修正した」「前回から変わったのは〜」「ご指示のとおり、一覧にまとめました」 | 渡された時点の文書だけを読む人に、文が要るか |
| 4. 作り手の作業（段取り・報告・予定）が残る | 「相手を待たずに進められる」「3件を補い、粒度をそろえた」「次回までに確認する」 | 文頭に「（書き手は、作業の中で）」を補って読めるか |
| 5. 作業の途中の出力が残る | 「〜は未達」「〜は不明であった」「〜は確認できなかった」「（要確認）」「TODO: 〜」 | 対象がどうなっているかではなく、書き手の作業がどこまで進んだかを言っているか |

直し方は群ごとに決まっている。

- 1 は、対象を主語にした文に書き換える。「本章では、業務を3つに分けて説明する」は「業務は、次の3つで成り立つ」にする。前提の宣言が対象の要件なら（「管理者の権限が要る」）、要件として書く。
- 2 は、まず消してみる。消して意味が通るなら消す。通らないなら、章の番号のように文書の中で特定できる形にする。参照先の中身が理解に必要なら、必要な分を本文に書く。
- 3 は、結論だけを残す。前のバージョンとの差を伝えたいなら、文書の外（送るときの返答・変更履歴）で伝える。
- 4 は、作業の段取りや報告を消し、条件・状態・結果だけを残す。次にすることを書くなら、読み手と合意した約束として書く。合意があったかが文書から分からなければ、直さずに「判断が要る」として挙げる。
- 5 は、読み手に必要な対象の状態なら、対象を主語にした状態や制約として書く（「認証は未確認」→「認証には対応していない」、「仕様は不明であった」→「仕様は未定」）。状態が分からなければ、直さずに「判断が要る」として挙げる。書き手の作業の進み具合だけなら消し、ユーザーへの返答で伝える。

群4はほかの群の形を取らないので見つけにくい。文書の一節がまるごと作り手の作業で区切られている（「自分たちでできること／相手を待つこと」）なら、文を直しても直らない。区切り方を、対象の側の軸（条件・確かさ・影響の範囲）に組み直す。

## 残すもの

次は、読み手が本文を読むのに使うので、メタ記述として扱わない。

- 本文で使う記号やラベルの定義（「推定の値には〔推〕を付ける」）。
- 文書が扱う対象の目的。文書の使われ方の説明にまで広げない。
- 出典と日付。
- 章の番号などで特定できる、文書の中の参照。
- 前のバージョンの数字からの差が、読み手の判断に必要なもの（見積・実績・目標で、いくら動いたか）。
- 読み手の注意を促す前置き（「ここで大事なのは〜」）。ほかの群にはっきり当たるときだけ直す。

迷ったら、文を消したときに、読み手の判断や理解が変わるかを考える。変わるなら残す。

## 手順

1. 文書を頭から順に読み、1文ずつ5つの群の質問で確かめる。見出し・表のセル・箇条の項目・注記も読む。
2. 当たった文を、群の直し方で直す。
3. 直したあと、もう一度頭から読む。直したことで、参照先が消えた文や、つながらなくなった文が無いかを見る。

文書の書き方の全体は規則「エージェントが書く文書は、文書だけで通じるように書く」（`writing-documents.md`）にある。セッションに読み込まれていなければ、remove-meta-narrative スキルのフォルダにある `references/writing-documents.md` を読む。

## 返し方

- メタ記述を除くように頼まれたときは、「場所／群／直す前 → 直した後」の一覧と、直した全文を返す。メタ記述か中身か決めきれない文は直さず、一覧に「判断が要る」として挙げる。
- 文書を渡す前に自分から使ったときは、直した文書を渡し、返答では使ったことを1行で伝える。一覧はユーザーに求められたら出す。
