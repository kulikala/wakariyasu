# README の書き方

README は、リポジトリの最上位に置き、ツールを外部に公開するための文書だ。読み手はツールを試すか
判断する人、インストールする人、使い始める人で、ツールが何であり、どうセットアップすれば使えるかを
README だけで知ろうとする。読み手は章の名前を手がかりに必要な所へ飛ぶので、日本語の README は、人が手で
保守している日本語の README で見慣れた章の名前・組み立て・言葉で記述する。

リポジトリに README の書き方を定めた文書があれば、先に読んで従い、リポジトリの文書が定めていない点を、各章の方針で補う。
各章の方針に無い章の名前や言い回しは、ファイルやウェブを読めるなら、同じ分野で人が
日本語の README を保守しているツールをいくつか開き、ツールの README で使われている形に合わせる。

## 章

章の並びと数はツールに合わせて選べる。読み手は何のツールかを知り、自分の環境で動くかを確かめ、
インストールし、使い始める、の順番に読み進めることが多いので、読み進める順番に沿う並びは探しやすい。
ツールに当てはまらない章は立てない。長くなる細部は別の文書に分け、README の該当する章からリンクする。

1つの章には、章の目的に当たる中身だけを記載する。読み手は章の名前で飛んで、飛んだ章だけを読むので、ほかの章の
中身が文の中に紛れると、探した章では見つからず、読んだ章の判断も揺らぐ。向かない用途の章で「…のオプションを
使うと〜できます」と使い方まで書きたくなったら、使い方は使い方の章に記載し、向かない用途の章からは使い方の章へリンクする。
1つの文を記述したら、文がどの章の目的に当たるかを確かめる。

章ごとの目的は次のとおり。

- 冒頭の説明：ツールが何をするかと、出力の例を示し、読み手が自分の用途に合うかをすぐに判断できるようにする。
- 機能：ツールに、利用者が別々に使える機能のまとまり（別のコマンドやモード）があれば、機能の名前と働きを、
  名前を初めて使う章より前に一覧で示す。名前の意味を知らないと、読み手は以降の章についていけない。
- 特長：ツールを選ぶ理由になる性質を記載する。出力の形式やオプションのような仕様は、使うときに探すので、
  使い方の章に置く。
- 向いている用途：ツールが受け持つ範囲と、向く用途・向かない用途を記載する。ツールの前後で利用者がする作業は、
  受け持つ範囲の説明として記載し、向かない用途に並べない。並べると、ツールを使う流れの一部が、合わない使い方の
  ように読める。
- 免責事項：ツールの出力の扱いと保証の有無を記載する。出力に誤りが残るツールなら、どんな誤りが残りやすく、利用者が何を
  確かめるかを記載する。損害の免責のような法的な文はライセンスに任せる。
- 対応環境：読み手が自分の環境で何が動くかを確かめられるように、表で示す。使いたい人が多いのに対応していない
  環境も表の行にして非対応と記載する。読み手は自分の環境を表の中で探すので、行が無いと対応しているかが分からない。
- 必要なディスク容量の章と、別途必要なソフトウェアの章：インストールの前に読み手が確かめることを、各章に
  まとめて記載する。ほかの章ではくり返さず、該当する章へリンクする。
- インストール方法：読み手が自分の環境の節だけを読めばよいように環境ごとに分け、どこで何を実行するかを記載する。
  節の名前と節の冒頭で、どの環境向けの方法かが分かるようにする。方法を比べた結果や選んだ理由の説明は、読み手が
  方法を選ぶのに必要な分だけにする。
- 使い方：最初の1回を動かすまでの手順と、よく使う操作を記載する。
- 開発者ガイドとライセンス：開発に参加する人に向けた手順と、利用の条件を記載する。

README が説明するのは、リポジトリが提供するツールだ。インストールや実行に使うほかのツール（パッケージマネージャー・
インストール用のコマンドなど）は、読み手が実行するコマンドと、そのコマンドに必須のオプションだけを示す。
必須でないオプションは、オプションを説明する欄でなければ、何ができるかを一言で示すだけにする。ほかのツールの動く条件や詳しい使い方は、ほかのツールの
README に任せ、リンクで示す。ほかのツールの仕様を書き写すと、ほかのツールが変わったときに README だけが古くなる。

保守していない古いバージョンを使う案内は記載しない。読み手が古いバージョンの手順を最新のバージョンの手順と取り違え、直らない不具合のあるバージョンを
使い始めるからだ。古いバージョンから移る利用者がいるなら、移る手順だけを記載する。

## 用語

読み手は翻訳調の言い回しや見かけない語に出会うと、文書を信頼しにくくなり、意味も取り違える。言葉は、人が手で
保守している日本語の技術文書で見かける語を選ぶ。

- 一般の語：作業や物を表す語は、日本語の技術文書で定着した語を使う。日本語では使わない言い回しと、代わりに
  使う語は、wakariyasu のスキル `check-terms` の一覧（`references/terms.tsv`）にある。一覧に無い語も同じ考え方で選ぶ。
- ツールの語：ツールのコマンドや画面、出力に出る語は、利用者が画面と見比べるので、変えずに使い、初めて出る所で
  意味を添える。
- 書き手の造語：書き手が作業の中で付けた呼び名は、ツールの外では通じないので使わず、中身を表す一般の語に
  替える。替えるときは、替えた語を英語に直し、元の呼び名が表すものの中身と合うかを確かめる。
- 章の名前：日本語の README で見かける名前を使う。英語の見出しを直訳した名前は、日本語の README では見かけない。
- 作業の章と節の名前：インストールや設定のように読み手が手を動かす章と節は、「インストール方法」「セットアップ方法」「アップデートの手順」のような、日本語の README で見慣れた名前にする。読み手は見慣れた名前を探して飛ぶので、和語に言い換えた名前では、探している章だと気付かない。本文の語も見出しと同じ語でそろえる。
