# スキルの目的

ユーザーが答えを読めば、自分が何を目指していて、作業がどこまで進み、判断してもらうことがあれば何を判断してもらうのかが分かるように記述する。状況は、ファイル・コマンドの出力・タスクの状態のように確かめられるものを確かめ、今の事実に合わせて記述する。

## 伝え方の方針

書き方は規則「ユーザーへの返答は、経緯を追っていない人が読んで分かるように記述する」（スキル `writing-rules` の `rules/writing-to-user.md`）に従う。

## 回答の構成

次の順番で記述する。記載することが無いセクションは、見出しごと省く。

```markdown
## 現在のゴール

<セッション全体で、何を、何のためにしているか>

## 直近の指示

<最後の依頼で取り組んでいること：何を、何のために>

## タスク

| # | タスク | 状態 | 背景・補足 |
|---|---|---|---|
| 1 | … | … | … |

## 直近のステータス

<今どこにいるか。直前に何が終わり、何が動いていて、次に何をするか>
```

ユーザーに判断してもらうことがあるときは、最後に「## 判断を求めていること」の節を足し、
「判断の問いかけの書き方」（スキル `writing-rules` の `references/asking.md`）の形で記述する。何を判断してもらうかは、規則「ユーザーへの返答は、経緯を追っていない人が読んで分かるように記述する」（`writing-to-user.md`）の「判断してもらうことだけを問いかけ、経緯を読まずに答えられる形にする」の節に沿って決定する。
エージェントが選んで進めたことは、「判断を求めていること」の節ではなく「直近のステータス」か「タスク」の背景・補足に記載する。

判断してもらうことが1つだけで、タスクの進み具合など、ほかに伝えることが無ければ、返答を「判断を求めていること」の節だけにしてよい。

見出し・表の列名・状態の語は、返答と同じ言語で表記する。

## タスクの状態欄の表記

状態欄は「絵文字＋状態の語」で表記する。次の 7 つは固定で、当てはまる場面では、表に記載した絵文字と状態の語の組を変えずに使う。

| 状態欄の表記 | 使う場面 |
|---|---|
| ✅ 完了 | 終わっていて、結果を確かめた |
| 🚧 作業中 | 今、エージェントが手を動かしている |
| ⏳ 処理待ち | 自分の手を離れて動いているもの（裏で動かした処理、サブエージェント、CI など）の終わりを待っている |
| 🙋 判断待ち | ユーザーが判断しないと進められない。判断を求めていることの番号を添える（例：🙋 判断待ち（1）） |
| 📝 未着手 | やることは決まっているが、まだ始めていない |
| ❗ 問題あり | 失敗した、または結果が想定と違って止まっている。何が起きたかを背景・補足に記載する |
| ⛔ 中止 | やらないことに決まった。誰の判断かを背景・補足に記載する |

絵文字を使わないようにユーザーに言われていれば、状態の語だけを表記する。

7 つのどれにも当たらない状態は、状態を表す絵文字と語の組を作って使ってよい。上の 7 つの絵文字はほかの意味に使わない。

状態欄の絵文字は意味を担うので、整えるときも残す。

## 送信前の確認

作成した報告を、規則「記述した文章は、渡す前に整える」（スキル `writing-rules` の `rules/polishing.md`）に沿って整える。yomiyasu は呼ばない。表の構造も残す。
