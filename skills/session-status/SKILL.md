# セッションの状況を答える

ユーザーが答えを読めば、自分が何を目指していて、作業がどこまで進み、決めてもらうことがあれば何を決めてもらうのかが分かるように書く。状況は、ファイル・コマンドの出力・タスクの状態のように確かめられるものを確かめ、今の事実に合わせて書く。

## 伝え方

書き方は規則「ユーザーへの返答は、経緯を追っていない人が読んで分かるように書く」（`writing-to-user.md`）に従う。セッションに読み込まれていなければ、session-status スキルのフォルダにある `references/writing-to-user.md` を読む。

## 答えの形

次の順番で書く。書くことが無いセクションは、見出しごと省く。

```markdown
## 現在のゴール

<セッション全体で、何を、何のためにしているか>

## 直近の指示

<最後の依頼で取り組んでいること：何を、何のために>

## タスク

| # | タスク | 状態 | 背景・補足 |
|---|---|---|---|
| 1 | … | … | … |

## 直近のステータス

<今どこにいるか。直前に何が終わり、何が動いていて、次に何をするか>
```

ユーザーに決めてもらうことがあるときは、最後に「## 判断を求めていること」の節を足し、
「判断の問いかけの書き方」（`asking.md`）の形で書く。セッションに読み込まれていなければ、session-status スキルのフォルダにある `references/asking.md` を読む。何を決めてもらうかは、規則「ユーザーへの返答は、経緯を追っていない人が読んで分かるように書く」（`writing-to-user.md`）の「決めてもらうことだけを問いかけ、経緯を読まずに答えられる形にする」の節に沿って決める。
エージェントが選んで進めたことは、「判断を求めていること」の節ではなく「直近のステータス」か「タスク」の背景・補足に書く。

決めてもらうことが1つだけで、タスクの進み具合など、ほかに伝えることが無ければ、返答を「判断を求めていること」の節だけにしてよい。

見出し・表の列名・状態の語は、返答と同じ言語で書く。

## タスクの状態欄

状態欄は「絵文字＋状態の語」で書く。次の 7 つは固定で、当てはまる場面では、表に書いた絵文字と状態の語の組を変えずに使う。

| 状態欄の表記 | 使う場面 |
|---|---|
| ✅ 完了 | 終わっていて、結果を確かめた |
| 🚧 作業中 | 今、エージェントが手を動かしている |
| ⏳ 処理待ち | 自分の手を離れて動いているもの（裏で動かした処理、サブエージェント、CI など）の終わりを待っている |
| 🙋 判断待ち | ユーザーが決めないと進められない。判断を求めていることの番号を添える（例：🙋 判断待ち（1）） |
| 📝 未着手 | やることは決まっているが、まだ始めていない |
| ❗ 問題あり | 失敗した、または結果が想定と違って止まっている。何が起きたかを背景・補足に書く |
| ⛔ 中止 | やらないことに決まった。誰の判断かを背景・補足に書く |

絵文字を使わないようにユーザーに言われていれば、状態の語だけを書く。

7 つのどれにも当たらない状態は、状態を表す絵文字と語の組を作って使ってよい。上の 7 つの絵文字はほかの意味に使わない。

状態欄の絵文字は意味を担うので、整えるときも残す。

## 送る前に

書いた報告を、規則「書いた文章は、渡す前に整える」（`polishing.md`）に沿って整える。セッションに読み込まれていなければ、session-status スキルのフォルダにある `references/polishing.md` を読む。yomiyasu は呼ばない。表の構造も残す。
