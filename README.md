# wakariyasu

[English](README.en.md)

wakariyasu は、AI エージェントが書く日本語を、作業の経緯を知らない人が読んでも分かるようにする、Claude Code のプラグインです。スキルの部分は、Codex や Cursor などのエージェントでも使えます。

エージェントに長い作業を任せると、報告や質問が、作業の途中でエージェントが付けた呼び名や、途中で決めた前提のまま書かれがちです。報告を読む人は「結局どういうこと？」と聞き返すことになります。wakariyasu は、エージェントがユーザーに返す文と、エージェントが書く文書（README・仕様書・コミットメッセージなど）の両方を、経緯を知らない読み手に通じる形で書かせます。

## 入れる前と後

同じ作業を終えたあとの報告です。

入れる前:

> 案Bでフック経由の注入にし、dependencies は外しました。

入れた後:

> 規則は、セッションの開始時に、プラグインのフック（決まった時点で自動で動く仕組み）から読み込ませる形にしました。yomiyasu への依存の宣言は外しました。宣言を残すと、yomiyasu を入れていない環境では wakariyasu ごと読み込まれないためです。

入れる前の報告は、作業中に使った「案B」「注入」や設定の名前で書かれていて、経緯を追っていない人には何が起きたのか分かりません。入れた後は、何をしたかと、なぜそうしたかが、報告だけで分かります。

## 規則とスキル

wakariyasu は、2種類の部品でできています。

- **規則**は、書き方の方針です。Claude Code のセッションが始まるたびに読み込まれ、毎回の返答と文書に当てはめられます。頼む必要はありません。
- **スキル**は、決まった場面で使う手順です。ユーザーが下の表の言葉で頼んだときと、報告や文書の受け渡しの場面でエージェントが必要だと判断したときに使われます。

## 使う場面

| 場面 | 言葉の例 | 使われる部品 | すること |
|---|---|---|---|
| いつもの返答 | （頼まなくても当てはまります） | 規則 `writing-to-user` | 返答を、経緯を知らない人に通じる語と形で書かせます |
| 状況を知りたい | 「現状は？」「残タスクは？」 | スキル `session-status` | 目指していること・タスクと状態・判断を求めることを、決まった形で報告させます |
| 返答が分からない | 「分かりやすく」「つまり？」「〜とは？」「〜の違いは？」 | スキル `explain-clearly` | 直前の返答や、その中の分からなかった語を言い直させます。「簡潔に」なら短く、「小学生でも分かるように」なら前提を足して説明させます |
| 文書を書かせる | （頼まなくても当てはまります） | 規則 `writing-documents` | README・仕様書・SKILL.md・コミットメッセージなどを、その文書だけで通じるように書かせます |
| 文書からメタ記述を除く | 「メタ記述を除いて」 | スキル `remove-meta-narrative` | メタ記述（「本章では〜」「ご指摘を受けて〜」のように、文書が自分自身や作った経緯を語る文）を見つけて直させます |
| 文書を人に渡す前 | 「公開前に見て」「読み手の目でレビューして」 | スキル `review-for-readers` | エージェントにサブエージェントを起こさせ、作業の経緯を渡さずに文書だけを読ませます。読み手が引っかかった箇所を直させます |

規則はほかに2本あります。`polishing` は、書いた日本語を渡す前に整える方法と、表記の選び方を決めています。`session-status` は、スキル `session-status` をどの場面で使うかを決めています。

## 表記の選び方

かなと漢字の使い分け・数字の書き方・体言止め・常体と敬体は、文章の種類によって変わります。wakariyasu はこれらを一律には決めず、エージェントに次の順で選ばせます。

1. ユーザーの指示（CLAUDE.md や AGENTS.md に書いた指示を含みます）
2. 同じ文書や同じリポジトリで、すでに使われている書き方
3. 文章の種類ごとの既定。たとえば、ユーザーへの返答は敬体の文で書き、コミットや PR の変更点の行は体言止めでもよい、とします。種類ごとの表は [`references/styles.md`](references/styles.md) にあります

決まった書き方にしたいときは、CLAUDE.md に1行で書いてください。たとえば「数字は算用数字で書く」「README は敬体で書く」と書けば、既定よりそちらが優先されます。

## yomiyasu との組み合わせ

[yomiyasu](https://github.com/nanaism/yomiyasu)（nanaism/yomiyasu）は、AI が書いた日本語の不自然な比喩や、主語と述語のずれを整えるスキルです。wakariyasu とは別の作者のものです。

yomiyasu がエージェントに入っていれば、wakariyasu は、長い返答や文書を渡す前に yomiyasu で整えさせます。そのとき、文章の種類（返答・PR・README など）も yomiyasu に伝えさせます。

yomiyasu が入っていなくても、wakariyasu は動きます。そのときは、長すぎる文・離れすぎた主語と述語・中身の無い飾りの語・「次の点が重要です」のような予告だけの文を、エージェント自身に確かめさせて直させます。

## 入れ方

### Claude Code に、プラグインとして入れる

Claude Code の中で、次の2つを打ちます。1つ目は、このリポジトリを入手先（マーケットプレイス）として登録します。2つ目は、そこから wakariyasu を入れます。

```text
/plugin marketplace add kulikala/wakariyasu
/plugin install wakariyasu@wakariyasu
```

規則とスキルの両方が入ります。yomiyasu も、同じ入手先から入れられます。

```text
/plugin install yomiyasu@wakariyasu
```

入ったかどうかは、新しいセッションで「現状は？」と聞いて確かめられます。「現在のゴール」「タスク」などの見出しのついた報告が返ってくれば、入っています。

### スキルだけを入れる（ほかのエージェントでも使えます）

GitHub CLI の `gh skill` コマンド（プレビュー版の機能）で入れます。

```sh
gh skill install kulikala/wakariyasu --all --scope user --agent claude-code
```

`--agent` には、使うエージェントの名前（`codex`・`cursor`・`github-copilot` など）を渡します。`--scope user` は、すべてのフォルダで使えるように、ホームディレクトリに入れる指定です。

スキルだけを入れた場合、規則はセッションの始めに読み込まれません。それでも、各スキルは自分のフォルダの中に規則の写しを持っていて、使われるときにそれを読みます。

### 規則を、Claude Code 以外のエージェントで使う

[`AGENTS.snippet.md`](AGENTS.snippet.md) は、4本の規則をつなげた本文です。AGENTS.md など、エージェントが毎回読む指示のファイルに貼ってください。

## このリポジトリを直す人へ

```text
rules/                  規則（4本）
references/styles.md    文章の種類ごとの表記の既定
skills/                 スキル（session-status・explain-clearly・remove-meta-narrative・review-for-readers）
hooks/                  プラグインとして入れたときに、セッションの始めに規則を読み込ませるフック
AGENTS.snippet.md       Claude Code 以外のエージェントに貼る、規則の本文
bin/build               rules/ と references/ から、スキルの中の写しと AGENTS.snippet.md を作る
```

規則と表記の既定は、`rules/` と `references/` だけで直します。直したら `bin/build` を実行し、スキルの中の写しと `AGENTS.snippet.md` を作り直してください。`bin/build --check` は、写しが `rules/` と `references/` の内容と食い違っていれば失敗します。
