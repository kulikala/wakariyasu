# README の書き方

README はツールを試すか決める人、インストールする人、使い始める人が最初に開く文書だ。読み手は章の名前を
手がかりに、必要な所へ飛ぶ。日本語の README は、人が手で保守している日本語の README（たとえば同じ分野の
有名なツールの README）と同じ章の名前・組み立て・言葉で書き、読み手が見慣れた形の中で探すものを
見つけられるようにする。

## 章の組み立て

ツールに当てはまらない章（GPU を使わない、モデルをダウンロードしない、など）は立てない。

- 機能に区分があるなら、区分の一覧を使い方より前に書く。機能がいくつの区分に分かれ、それぞれが何をするかを、
  区分の名前・コマンド・説明の表で示す。区分の名前を説明する前に使うと、読み手は以降の表や節についていけない。
  区分が1つだけなら、表は立てずに冒頭の説明で足りる。
- 対応環境は対応表で書く。読み手は自分の PC で何が動くかを知りたいので、OS ごとに、機能の区分が使えるか、
  CPU と GPU のどちらで動くかのように、自分の環境に当てはめられる表にする。どこまで試したかのような
  作業の記録は書かない。README は作業の報告書ではない。
- ダウンロードするモデルやデータが大きいなら、必要なディスク容量を独立した章にする。列は「機能区分」
  「ダウンロードするモデル」「用途」「容量」とし、そのモデルが何のために使われるかを用途の列に書く。
  読み手は使う機能区分の行を足せば、必要な容量が分かる。
- ツールに含まれず、利用者が各自でインストールするソフトウェアは、「別途必要なソフトウェア」の章に
  まとめ、各自でインストールするよう案内する。列は「ソフトウェア」「バージョン」「要否」「説明」とし、
  要否の列には必須か任意かを書く。任意なら、どんな場面で必要になるかを添える。ほかの章では、ソフトウェアを
  利用者が自分でインストールすることを地の文で述べず、この章へリンクする。
- インストールの章は OS ごとの節（「macOS の場合」「Linux の場合」「Windows の場合」）に分け、
  どこで何を実行するかだけを書く。インストールスクリプトの中の動き、対応環境、容量、別途必要な
  ソフトウェア、使い方は、それぞれの章に置く。対応していない OS は対応環境の章に書き、インストールの章で
  「〜では動きません」と案内しない。
- 章の名前は、人が手で保守している日本語の README で使われている名前に合わせる。英語の見出しを直訳した
  名前（Development を「開発」）は、日本語の README では見かけない。開発に参加する人向けの章は
  「開発者ガイド」、AI エージェント向けのスキルの章は「エージェント・スキル」とする。ほかの章の名前で
  迷い、ファイルやウェブを読めるなら、同じ分野の日本語の README をいくつか開いて確かめる。
- 保守していない旧版を使う案内は書かない。旧版があり、そこから移る利用者がいるなら、移るときの手順だけを書く。

## 言葉

- 日本語の技術文書で使わない言い回しは、使われる言い回しに替える。翻訳調の言い回しは読み手に
  文書を信頼しにくくさせる。迷ったら、その言い回しを人が手で保守している日本語の技術文書で見かけるかで
  決める。このガイドを書いたユーザーが直した例は次のとおり。
  - コマンドを「打つ」は「実行する」。
  - 「旗」は「オプション」。
  - 「導入」は「インストール」か「セットアップ」。
  - 「要る」は「必要な」「必要です」、「別に」は「別途」。
  - 「やること」は「対応内容」。
  - 表の列の「使う機能」「取得するもの」は「機能区分」「ダウンロードするモデル」。
- 「端末」は PC やスマートフォンのような機器を指す。コマンドを実行するアプリは「ターミナル」と書く。
- 書き手が作った呼び名は、ツールの外では通じないので使わない。たとえば、まとめて渡すデータを「束」と
  呼ぶような造語は、一般の語に替える。替える語は英語に直したときに指すものの中身と合うかを確かめる。
  LLM に渡す指示と依頼をまとめた JSON を「問い」と呼ぶと、英語では question になり中身と合わない。
  中身に合う「プロンプト」と呼ぶ。

## 仕上げ

書き終えたら、規則 `writing-documents` の「書き終えたら」の順で仕上げる。yomiyasu で整えるときは、
文書の種類として `article`（技術記事・README）を渡す。
